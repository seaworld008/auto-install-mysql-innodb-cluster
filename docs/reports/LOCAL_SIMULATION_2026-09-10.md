## 稳定的成员发现

三节点接入层布局使用无法从其他数据库与所有 Router 节点解析的系统主机名：15 次跨节点解析检查全部返回无结果。Linux 本机 NSS 解析自身名称属于正常行为，单独记录，不与跨节点解析混淆。

设置 `mysql_report_host_override: "{{ ansible_host }}"` 后，集群元数据记录三个 IPv4 地址。完整部署通过后，删除该覆盖项再重跑：实际通告 IP、元数据端点、MySQL 配置摘要和 PID 均保持不变。

另在已有混合集群上验证：不指定新地址时保留原主机名；显式改成不同地址时，部署在写入配置或重启之前拒绝。已有节点身份与 Router keyring 保持。

## 持续写入、故障与扩缩容

每次尝试使用唯一测试 ID；客户端收到成功才记录 ACK。完成后逐条核对已确认 ID 与内容，超时但实际已提交的记录单列，不宣称 exactly-once。下表为观测到的最大 ACK 间隔，不能替代生产 RTO。

| 场景 | 已确认写入 | 失败尝试 | 最大 ACK 间隔 |
| --- | ---: | ---: | ---: |
| 滚动文件句柄配置 | 2021 | 2 | 3.474 秒 |
| 独立部署 c6aa6c4 重跑 | 2610 | 1 | 3.403 秒 |
| 共置完整重跑 | 1448 | 0 | 0.755 秒 |
| 混合完整重跑 | 1426 | 0 | 0.761 秒 |
| 三节点接入重跑并移除地址覆盖 | 2940 | 0 | 0.819 秒 |
| MySQL 第四成员加入 | 822 | 0 | 0.826 秒 |
| 切主并摘除第四成员 | 88 | 1 | 0.670 秒 |
| Router/LB 扩缩容 | 4154 | 5 | 1.004 秒 |
| 已有成员通告地址保持升级 | 1383 | 2 | 3.844 秒 |
| 停止 primary 服务 | 558 | 1 | 3.423 秒 |
| 停止活跃 Router | 580 | 1 | 1.203 秒 |
| 停止 HAProxy | 564 | 14 | 3.498 秒 |
| 停止 Keepalived | 575 | 2 | 1.795 秒 |
| 数据库容器突然停止 | 448 | 78 | 24.769 秒 |
| 入口容器突然停止 | 565 | 2 | 3.520 秒 |
| 共置整机突然停止 | 452 | 52 | 25.110 秒 |

这些场景的全部已确认写入均保留，故障后恢复完整健康。接入层扩缩容的写入探针从已有 Router 的收敛阶段开始覆盖至 LB 缩容；缩容至双节点后，继续缩为单节点的请求被 HA 门拒绝。MySQL 扩容实际完成第四成员加入、切至该成员，再切主摘除。

### 多数派丢失与完整停机恢复

多数派丢失时写入保护通过。25 秒的自动恢复观察未通过，之后执行受控完整停机恢复：先核对节点，dry-run，再执行不带 force 的 AdminAPI 恢复。存活 primary 的停机曾等待未完成事务，实验记录了单节点强制终止与崩溃恢复。恢复后全部已确认写入保留。此结果不代表多数派故障能够自动自愈。

另一次完整 VM 停机后的恢复，在确认全部成员离线和 GTID 一致后执行，恢复调用耗时 6.23 秒。故障处理步骤见 [恢复手册](../runbooks/TROUBLESHOOTING.md)。

## 备份与隔离恢复

逻辑备份和 XtraBackup 均通过主入口执行。第四成员摘除停服后进入另一 internal 网络，确认原三节点的 3306/33061 不可达；恢复时禁用自动加入复制组、加载持久变量、启动复制通道和事件调度，并生成新的实例 UUID。原集群恢复前后的业务数据摘要相同。

| 备份 / 恢复 | 结果 | 核对内容 |
| --- | --- | --- |
| 逻辑备份与业务 schema 导入 | 通过 | events 11040 行、type_samples 8 行、auto_ids 10 行，数据 SHA-256 相同；字段、索引、约束与表选项逐项相同 |
| XtraBackup 与隔离 copy-back | 通过 | 同样的业务数据与原始 DDL 摘要全部相同，恢复后的复制隔离状态通过 |
| 1 MiB 限定文件系统写满 | 通过 | 独立确认 ENOSPC；备份返回非零且不生成成功清单，卸载后集群健康 |

逻辑导入的 SHOW CREATE TABLE 多了冗余字符集声明；保存差异并比较结构语义后确认一致，没有静默忽略结构差异。物理产物的检查点为 `full-prepared` 且压缩残件为零，清单记录实际状态；直接在工作副本上 copy-back，避免再次解压覆盖已准备的数据页。

恢复校验使用备份时的基线，不要求旧备份包含后续写入。逻辑恢复验证业务 schema，不代表生产账号权限和完整灾备拓扑已验收。
